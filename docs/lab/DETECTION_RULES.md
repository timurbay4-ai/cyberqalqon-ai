# CyberQalqon Lab Detection Rules

## Custom rules

| Rule | Level | Source | Behavior | Delivery |
|---|---:|---|---|---|
| `100101` | 10 | Nginx access log | Existing six-event/30-second HTTP 4xx enumeration correlation | CyberQalqon |
| `100110` | 1 | Kernel/nftables | Seed event for one authorized loopback TCP SYN | Wazuh archive only |
| `100111` | 10 | Kernel/nftables | Six different destination ports from the same source to the same destination in 30 seconds; 60-second suppression | CyberQalqon |
| `100120` | 8 | Nginx access log | Exact nonexistent sensitive-path probes: `/.env`, `/.git/config`, `/wp-admin`, `/server-status`, `/actuator/env` | CyberQalqon |
| `100130` | 7 | Realtime FIM | File added directly below `/etc/cyberqalqon-lab` | CyberQalqon |
| `100131` | 9 | Realtime FIM | File modified directly below `/etc/cyberqalqon-lab`; MITRE `T1565.001` | CyberQalqon |

The integration allowlist is `100101,100111,100120,100130,100131`. Level-1 seed events are intentionally not forwarded.

## Network correlation design

`100111` inherits only the tagged `CQ-NETSCAN` events generated by the bounded nftables rule. It requires:

- the same decoded source IP;
- the same decoded destination IP;
- a different decoded destination port;
- six matching seed events inside 30 seconds.

The rule describes behavior as a possible port scan. It does not claim that the scanner was Nmap because packet telemetry cannot reliably identify a scanner brand.

Validated false-positive controls:

- one closed-port connection did not produce `100111`;
- one ordinary HTTP `/` request did not produce `100120`;
- six ports spread over 42.11 seconds did not produce `100111`;
- seed events remain level 1 and are not sent to CyberQalqon.

## Web rule limitations

Rule `100101` uses Wazuh's `different_url` correlation. This demonstrates changes between correlated URLs, but it must not be described as an exact distinct-set cardinality calculation. The bounded Gobuster regression still produced the expected alert.

Rule `100120` uses a small exact allowlist of suspicious request paths. Query strings are allowed, but prefix and substring matches are deliberately avoided to reduce benign matches.

## FIM rule design

The new realtime FIM scope is a disposable lab directory, not a production system file. Rule `100130` inherits Wazuh rule `554` (new entry), and `100131` inherits rule `550` (integrity changed). Test fixtures are benign and contain no secrets.

## Built-in rules validated synthetically

| Rule | Level | Fixture | Result |
|---|---:|---|---|
| `5710` | 5 | Invalid SSH username failure | Decoder and rule match PASS |
| `5712` | 10 | Eight invalid-user failures from one loopback source in 120 seconds | Correlation PASS |

These SSH results are `SYNTHETIC_FIXTURE` only. SSH was not enabled and no network authentication attempts were made.

## Rule file validation

All deployed custom rule files passed `/var/ossec/bin/wazuh-analysisd -t`. Representative network, web, and SSH events were evaluated with `/var/ossec/bin/wazuh-logtest` before active testing.
